# Офлайн-установка и обновление DVT

Эти скрипты предназначены для архива, собранного Denvic Distributor.
Корневой `install.sh` репозитория запускает онлайн installation_manager;
для офлайн-архива используются отдельные входные точки из этого каталога.

## Состав архива

```text
install.sh                  # install.sh или update.sh выбранного тега
offline-runtime.sh
offline-config.py
docker-compose.yaml         # выбранный Git-тег; локальные теги образов, pull_policy: never
images/*.tar                # все образы Compose, включая installation_manager
docker/<os>/<version>/*.deb  # только архив установки
```

Distributor заменяет `{version}` в скрипте на выбранный релиз.
Дополнительные файлы должны находиться рядом со скриптом.
Номер версии нельзя переопределить на другой релиз: Compose и образы
соответствуют версии архива. Для проверки исходного шаблона в вручную
подготовленном комплекте допустим `--version`.

## Установка

Распакуйте архив на Linux/amd64 и запустите:

```bash
sudo bash ./install.sh -n --dir /var/lib/dvt \
  --public-url https://dvt.example.org --external-port 80 --workers 2
```

Без `-n` новая установка предлагает ввести публичный URL.
Значения по умолчанию: каталог `/var/lib/dvt`, URL `http://localhost`,
порт `80`, один task-worker, MCP выключен. Для MCP предусмотрены
`--ai-mcp` и `--no-ai-mcp`.

Если Docker отсутствует, скрипт устанавливает локальные deb-пакеты через
`dpkg -i` и включает службу. ОС и версия должны совпадать с выбранными при
скачивании архива; системные зависимости deb-пакетов должны быть уже установлены.
При существующем Docker требуется рабочий Compose v2.
После загрузки образов конфигурация формируется внутри одноразового контейнера
`installation_manager:<версия>` с `--network none` и `--pull never`.
Python на хосте не требуется. Секреты генерируются теми же доменными функциями,
что и в штатном installation_manager.

Создаются `.env`, `installation/instance_id`, каталоги данных и расширений.
Скрипт проверяет Compose и наличие всех локальных образов, затем запускает
сервисы с `--pull never --no-build`. Постоянный installation_manager
для этой установки не запускается.

## Обновление

Скачайте **архив обновления**, распакуйте в отдельный каталог и выполните:

```bash
sudo bash ./install.sh -n --dir /var/lib/dvt
```

В архиве обновления входная точка `update.sh` называется `install.sh`.
Укажите существующий каталог DVT; без его `.env` обновление прекращается.
Сохраняются данные, `instance_id`, пароль PostgreSQL, Fernet, JWT-ключи,
параметры MCP и добавленные вручную настройки. Для старого `.env` недостающие
ключи подписи выводятся из существующего Fernet так же, как в штатной миграции.
Параметры URL, порта, количества worker и MCP меняются только при передаче
соответствующих флагов.

Перед изменениями сохраняются резервные копии `.env` и Compose в каталоге
DVT; каталог данных не удаляется. Compose пересоздаёт изменённые контейнеры.
Это обновление приложения, не резервное копирование базы данных и не
автоматический откат миграций.

## Старые релизы

Скрипты должны входить в Git-тег релиза. Для 1.22.0, где их ещё нет,
Distributor использует явно настроенный S3-комплект через `script_overrides`
в `products.yaml`. Совместимые копии находятся в
`services/offline_download/seed_data/dvt/` репозитория Distributor.
Подготовка конфигурации проверена с образом installation_manager 1.22.0.
