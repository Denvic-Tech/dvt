# Тесты

## Структура

- `tests/unit/` — модульные тесты. Структура директорий должна зеркалить исходники.
  Пример: `src/crud/project/read.py` -> `tests/unit/src/crud/project/read/`.
- `tests/integration/` — интеграционные тесты (в разработке).
  Часть legacy-наборов пока находится в `tests/intergration/` и требует миграции.
- `tests/fixtures/` и `tests/data/` — общие фикстуры и тестовые данные.

## Принципы

- Разбивайте тесты по категориям: лучше несколько небольших файлов, чем один большой.
- Unit-тесты не должны обращаться к внешним сервисам.
  Для БД используется in-memory SQLite или фикстуры.
- Интеграционные тесты планируется запускать через `testcontainers`.
- Часть тестов устарела — проверяйте актуальность при изменении функционала.
- Integration-тесты должны падать, если Docker недоступен.

## Запуск

```bash
{venv_dir_path}/Scripts/python.exe -m pytest tests/unit
```

Интеграционные тесты будут запускаться отдельно, по мере готовности набора.
