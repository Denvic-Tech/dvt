# Этап 05: Мигратор, применение полного Compose и готовность

- **Статус:** см. [план](../../plan.md).
- **Утверждённое ТЗ:** [spec.md](../../spec.md), приложение A.
- **План:** [plan.md](../../plan.md).
- **Зависимости:** 01–04 — проверенный план, исполнитель, guard и копия.
- **Покрытие:** REQ-02, 13, 18–19, 21, 24–26; AT-04, AT-06, AT-08, AT-10.

## Цель этапа

Выполнять обновление и чистую установку через полный Compose с отдельно подтверждённой миграцией и наблюдаемой готовностью.

## Контекст

`docker-compose.yaml`, `docker/docker-compose.*.yaml`, `services/gateway/{docker/prod.Dockerfile,migrate.py}`, `src/utils/waiting.py`, `migrations/AGENTS.md` и release Bake.

## Объём работ

1. Ввести одноразовый migrate из того же digest Gateway, без портов/socket, с readiness PostgreSQL, проверкой связки исходной/целевой ревизии, исключительной блокировкой и привязкой результата к операции, комплекту и фактической БД. Сохрани обработку неуспеха расширений и отрази required extensions в readiness. Старая запись exit 0 не открывает новый/восстановленный экземпляр.
2. Определи service_completed_successfully для прикладных служб; мастер независим. Прикладные процессы на старте проверяют ожидаемую схему; Gateway не мигрирует автоматически в новом образе. Протестируй dev и CI Compose там, где меняется их поведение.
3. Применяй полный Compose без списка сервисов приложения. Данные и профили сверяются по подготовленному плану. Чётко раздели migrator done, readiness (включая Proxy по адресу клиента, Orchestrator, Scheduler, воркеров и AI MCP при включении), атомарную фиксацию и завершение возобновления. Идемпотентно завершай возобновление после сбоя.
4. Сверь медленный старт Gateway, рассинхронизацию MCP, неполный запуск и прерывание: успех нельзя вывести из тега, старого exit 0 или единичного healthcheck. Учитывай собственную замену мастера.

## Не входит в этап

Разрушительное восстановление, опубликованный каталог и production rollout.

## Контракты и инварианты

Прежний комплект и копия сохраняются. Начатую или неизвестную миграцию следует сначала согласовать с наблюдаемой ревизией, lock и результатом одноразового контейнера. Тот же целевой комплект повторно использует результат только при подтверждении.

## Критерии приёмки

- [ ] `SAC-01`: Чистая установка и переход выполняют миграцию успешно; при ошибке HTTP Gateway и зависимые роли не стартуют преждевременно, мастер доступен.
- [ ] `SAC-02`: Два мигратора не меняют схему одновременно, чужой старый exit 0 не принимается, обязательные расширения соблюдаются.
- [ ] `SAC-03`: При позднем Gateway можно подтянуть зависимые сервисы; до полноценной готовности и возобновления операция не завершена.

## Проверки

Проверить затронутые CI/dev overlays. Python запускать через venv соответствующего репозитория с абсолютным корнем в `PYTHONPATH` там, где это требует AGENTS.md.
