- **Статус:** см. [план](../../plan.md).

- **План:** [plan.md](../../plan.md).

- **Покрытие:** REQ-01, 03, 10, 12–13, 20–23, 29–30; части AT-01, AT-04, AT-05, AT-13.

## Цель этапа

Передавать сохранённую операцию независимому временно запущенному исполнителю; сохранить защищённую доступность мастера.

## Контекст

`install.sh`, `services/installation_manager/{install.sh,docker-compose.yaml,Dockerfile,api.py,main.py,frontend/}`; текущие команды и маршруты имеют внешних клиентов.

## Объём работ

1. Одна документированная команда, интерактивные и заранее заданные параметры. Повтор возвращает существующий адрес, сохраняет identity, обнаруживает коллизии до изменения ОС, раздельно хранит bootstrap и release Compose; подготовка Docker требует явного согласия и доверенного источника.
2. Реализуй безопасную точку входа loopback по умолчанию, одноразовую привязку с истечением, TLS и авторизацию для заявленного удалённого сценария. Изолируй браузерные привилегированные запросы (сессия, origin/CSRF) и защищённый машинный вход. Не добавляй анонимный доступ к конфигурации, операциям и журналу, не передавай чувствительные значения в общем URL или журналах.
3. Введи основной API сохранения и чтения операций, контролируемую совместимость старых точек входа. Фиксируй запрос до 202; запускай фиксированный digest исполнителя вне проекта, не публикуя порт. Перед заменой мастера требуй подтверждение, владение и совместимость версии журнала. Реализуй защищённую типизированную передачу и host recovery/restart для systemd без постоянно работающего дополнительного сервиса.
4. Проверь кандидатный handoff через реальное пересоздание мастера и смену процессов; сохрани адрес и ID активной операции. Пока этапы применения и восстановления не приняты, не включай новый путь обновления по умолчанию.

## Не входит в этап

Применение схемы приложения, автоматический возврат после миграции, общий release gate, основная форма UI DVT.

## Контракты и инварианты

Временные контейнеры не владеют журналом через writable layer; Docker API не доступен из браузера; привилегированные операции ограничены экземпляром. Старый управляющий контур не должен обходить новый guard после переключения на него.

## Критерии приёмки

- [ ] `SAC-01`: Повтор bootstrap возвращает тот же адрес, путь, порт и identity; коллизия обнаружена до перезаписи.
- [ ] `SAC-02`: После пересоздания мастера и перезагрузки тестового хоста доступна та же операция с подтверждённым владельцем; UI не теряет ID в существующей вкладке.
- [ ] `SAC-03`: Анонимные, повторные токены и неподходящие origins не получают управление; noninteractive bootstrap не ставит зависимости без согласия.

## Проверки

`python -m pytest tests/unit/services/installation_manager`; сборка мастера по его `package.json`; shell syntax; isolated Linux Compose и контрольный reboot systemd. Никаких изменений хоста разработки или удалённых рабочих установок. Python запускать через venv соответствующего репозитория с абсолютным корнем в `PYTHONPATH` там, где это требует AGENTS.md.
