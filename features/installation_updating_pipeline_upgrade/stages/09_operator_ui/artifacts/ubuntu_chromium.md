# Независимая проверка мастера и основного UI в Chromium

Стенд: Ubuntu 24.04 LTS, Linux amd64, 2 CPU, около 4 ГиБ RAM/30 ГБ, Engine
29.10.0, Compose 5.7.1. Использовались отдельный проект, тестовые TLS CA,
Ed25519 trust и синтетическая учётная запись. Мастер `https://localhost:19169`
и DVT `http://localhost:18169` были доступны браузеру через SSH на loopback.
TLS каталога и реальное соединение Gateway → мастер проверены с CA. Chromium
запущен с отдельным тестовым контекстом для сертификата стенда.

| Проверка | Результат |
| --- | --- |
| Поставка рабочего комплекта | Linux Bake Gateway и двух digest мастера, включая новый UI мастера. Независимая сборка основного UI Linux amd64: `sha256:dd5264e86c48f753f9aceb15a8b69fc89603b48b7d8028b93a1ab0403c608546`. Образ передан с проверкой SHA-256, затем извлечён по OCI leaf через временный TLS Registry. |
| Bootstrap | Один административный запуск выдал отдельный код привязки, установил runtime на нестандартном порту, использовал подписанный каталог по TLS на закрытом Docker bridge. |
| Первый запуск | Chromium выбрал рекомендованный stable `1.25.0`, открыл дополнительные настройки и включил AI MCP. Ответ на принятый POST намеренно потерян, вкладка нашла тот же ID `d0448d65-598f-4cb7-b04d-927ceb833177`; manifest `sha256:dfc47986bb113b39211855a52efa4bf909f234721c04baa2cb829865ce64dc2a`, схема `0070`, `succeeded`. |
| Привязка и доступ | У неавторизованного браузера 401 к мастеру и 403 на создание администратора. Повтор кода привязки и чужой origin отклонены. Ссылка на `/setup` использовала фрагмент; браузер отдельно подтвердил привязку. Повтор кода первичной настройки отклонён. |
| Email и первый вход | Неверный email получил HTTP 422 с `loc` поля. Chromium создал первого администратора и вошёл в DVT. Gateway подтвердил завершение первичной настройки мастеру. Полный браузерный цикл после bootstrap: 81,237 с. |
| Привилегии и диагностика | Реальный Gateway видел только read-only CA и отдельный service token; связь Gateway → мастер по защищённому TLS прошла, токен не дал вызвать маршрут браузерной сессии. Выгрузка по ID не содержала синтетического email/пароля и кодов привязки. |

Первое ревью воспроизвело падение профиля после успешных ответов Gateway
на active, history и releases: HTTP JSON `null` был превращён сгенерированным
клиентом в `{}`, а UI пытался фильтровать отсутствующие действия. Виджет
теперь проверяет форму операции. Десять независимых тестов Vitest проверили
пустой журнал, защищённый setup и удержание страницы текущего обновления;
25 независимых тестов Gateway подтвердили маршруты и границу обслуживания.

После исправления повторная установка на новом каталоге данных прошла по
`5c5526f4-cf44-4a7f-9ae1-21750b303c10`, manifest
`sha256:49652fc86c4b986bb9d821b5d8bc857fd70050885bbfe7be7cdd5e187efbf41e`.
Браузерный цикл до первого входа повторён за 78,080 с. Linux UI этого прогона —
`sha256:61d8f72ad71d9ed209f0289fe65ab2b2b3ac01d40aa64e3de9d89de2e60b990d`.

При следующем ревью расчёт места остановил подготовку при 9,267 ГБ свободного
места. Для CA и service token Gateway использует отдельные проверенные
read-only файловые bind mount. Исправление исключило только эти два mount
из оценки постоянных каталогов. Регрессия покрыта тестом с реальными файлами.

Итоговая установка в новом каталоге завершилась за 81,702 с. ID
`aad3fb4c-990a-4804-9ce9-3269b7634d74`, схема `0070`, stable manifest
`sha256:a206a2dfbc7a67677ee099be3c3dfad5f8d21552c7c9f961c525e8fae1e746fd`.
Первый администратор вошёл, Gateway подтвердил настройку мастеру.

| Проверка обновления | Результат |
| --- | --- |
| Подготовка через основной UI | Суперадмин увидел `1.25.0 / 0070` и защищённую ссылку, отдельно подтвердил выбор RC. В плане указаны обе ревизии, профиль AI MCP и пропуск плановых запусков с сохранением существующих retry. Исходный Gateway продолжал отвечать 200. |
| Подтверждение | Запрос без CSRF получил 403, попытка применения без подтверждения получила 422. Подтверждение кнопкой в основном UI вернуло 202. Независимая ссылка содержала тот же ID `8fcc8c8a-71d6-4706-a696-1464f6122dcf`. |
| Detached update | Во время копирования рабочий компьютер выключили. Исполнитель на Ubuntu завершил тот же ID со статусом `succeeded`, `1.25.1-rc1 / 0070`, manifest `sha256:afed46a27256fe12403623ebe8e35d71ca947a9fbc4dd60911092a6f1a861c10`. Контейнеры Gateway и мастера заменены, PostgreSQL сохранил ID. Gateway HTTP и мастер HTTPS ответили 200. |
| Резервная копия | Манифест `sha256:e18f0e81a6d6860959b20d103e87b1bf933f4172617625d3ae720cf9af45e570` с тем же ID и исходной схемой `0070`. Сверены хеши и формат архива, `pg_restore --list` прошёл, gate PostgreSQL открыт. |
| Возврат оператора | После включения компьютера Chromium открыл тот же ID из независимой ссылки. Искусственный обрыв запроса показал сообщение о перезапуске, после возобновления запросов вкладка автоматически перезагрузилась и сохранила ID. Исходная учётная запись вошла, основной профиль отобразил новую версию и тот же успешный результат в истории. Результат проверки получен за 9,771 с. |

Это локальные комплекты функциональной приёмки из рабочих снимков. Стенд
использовал предустановленный Docker. Точные коммиты сборок, установка Docker
с нуля и сквозной цикл выпуска входят в этап 10.
