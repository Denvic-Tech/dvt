- **Повторное ревью:** оба замечания закрыты. Этап принят по [реальному прогону Ubuntu](./artifacts/ubuntu_chromium.md).
- **Связь с ТЗ:** SAC-02, SAC-03, REQ-14, 16, 22–23.
- **Назначение:** исходной сессии `/root/stage09_operator_ui`; тот же этап и набор требований.

Чистый браузерный путь установки прошёл до авторизованного первого входа.
На вкладке `/profile/update` HTTP 200 от manager, active, history и releases.
После загрузки интерфейс падает в глобальную границу ошибок:
`TypeError: Cannot read properties of undefined (reading 'filter')`. Клиент
Axios нормализует JSON null от `GET /api/update/operations/active` в `{}`;
виджет неверно трактует ответ как активную операцию. Каталог возвращает
фактическую версию и полный `first_steps`. Дополнительно общий экран
обслуживания не должен снимать защищённый маршрут текущего обновления в
профиле и терять ID, пока закрыт приём задач.

Исправить трактовку отсутствующей операции и сохранение страницы текущей
операции при временном отключении Gateway/мастера. Не ослаблять авторизацию
и не обходить запрет мутаций во время окна. Добавить адресную регрессию с
фактическим `{}`, перепроверить типы и браузерный сценарий после сборки.
Не менять ТЗ, исходную привязку или прочие профили. Обновить `report.md`.
