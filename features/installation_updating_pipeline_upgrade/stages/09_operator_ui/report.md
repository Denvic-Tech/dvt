# Отчёт об этапе 09. Установка и обновление в браузере

- **Статус:** `READY_FOR_REVIEW`
- **Задание:** [task.md](task.md)
- **Режим:** `FIX`, исходный прогон `IMPLEMENT` сохранён в отчёте.

## 1. Что сделано

- Мастер принимает закреплённую версию из защищённого каталога. Он показывает рекомендуемый stable, отдельный RC и первую ступень допустимого перехода. Установка и обновление сохраняются до передачи исполнителю. Повтор запроса использует уже зарегистрированный ID.
- Отдельный ключ первичной настройки доступен после подтверждённой готовности установки. Gateway обменивает этот ключ на короткую HttpOnly-сессию, связанную с ID установки. Ссылка передаёт ключ во фрагменте. Невалидный email возвращается ошибкой поля, завершённая настройка переводит на вход.
- Профиль суперадминистратора показывает фактические версии и схему, состав изменения, резерв места, правила очереди и расписаний. После подготовки отдельное подтверждение запускает окно обслуживания. Gateway проверяет роль, Origin и CSRF. Он соединяется с мастером по проверенному HTTPS с отдельным узким токеном.
- Защищённый адрес мастера доступен до простоя. Вкладки сохраняют выбранный ID, последнюю подтверждённую стадию и возвращаются к опросу при восстановлении связи. Доступны журнал, диагностика и действия из состояния исполнителя. Запуск уже подготовленной точки восстановления требует отдельного подтверждения.
- Для защищённой установки старый запрос `POST /update/run` читает существующее состояние или отвечает 410. Текущий legacy-путь без opt-in сохраняет совместимость. Документация описывает bootstrap, подключение, setup, подтверждение применения и восстановление.

## 8. Итерации исправлений

### Итерация 1 — замечания независимого Chromium

- Свежий профиль получал JSON null. Сгенерированный Axios возвращал `{}`, и виджет падал при обращении к списку действий. Входное значение нормализуется по `zOperationView`, пустой объект больше не создаёт ложную операцию.
- Общий экран обслуживания сохраняет профиль аутентифицированного оператора при наличии сохранённого ID. Gateway допускает GET текущих сведений о пользователе, а остальные запросы по этому пути и бизнес-мутации продолжают блокироваться во время окна.
- Добавлены регрессии с фактическим `{}` и проверки удержания страницы по ID. В отборе Gateway профиль доступен только на чтение. Прошли 180 pytest и 24 Vitest, сборка основного UI PASS. Повторный Chromium открыл профиль и передал обновление исполнителю.


### Итерация 2 — учёт диска при подготовке уже установленного DVT

- Повторный Chromium открыл профиль и принял обновление с ID `b6b9fa40-d2b7-4fe5-befc-0828df2a4902`. Подготовка завершилась `disk_space` при 9,267 ГБ свободного места. Рабочее приложение продолжило отвечать, окно обслуживания и копирование ещё не начинались.
- При сравнении работающего Gateway два точных read-only mount с CA и токеном правильно исключались. Однако при расчёте места оставался ненормализованный список, и проверка файловой системы получала файлы вместо каталогов.
- Список нормализуется до планирования диска. Два теста прошли с существующими файлами и каталогами при вызове `check_filesystems`. Посторонний read-only mount по-прежнему отклоняется. Повторный прогон на Ubuntu завершил обновление с прежним PostgreSQL. Финальный отбор Python — 182 passed, 6 платформенных пропусков.
