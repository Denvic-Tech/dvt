# Этап 07: Каталог релизов и атомарная готовность Distributor

- **Статус:** см. [план](../../plan.md).
- **Утверждённое ТЗ:** [spec.md](../../spec.md), приложение A.
- **План:** [plan.md](../../plan.md).
- **Зависимости:** 02, 05–06 — формат манифеста и клиентские проверки.
- **Покрытие:** REQ-05–08; AT-11.

## Цель этапа

Переиспользовать проверку полноты и предоставить совместимые релизы по каналу, платформе и исходной версии.

## Контекст

Репозиторий Distributor от корня backend — `../../denvic-distributor`; владельцы: `services/dvt_distribution`, `services/offline_download/infra/{release_catalog,registry_images,git_deployment}.py`. Клиент — `services/installation_manager` backend.

## Объём работ

1. Реализуй список версий и получение signed manifest по маршрутам §4. Нормализуй SemVer/RC формы, фильтры, переходы, отсутствие новой совместимой версии; RC отдельного канала. Переиспользуй существующую проверку тегов, артефактов и полноты Compose.
2. Сделай неизменяемую запись готовности по manifest digest и атомарный клиентский интерфейс. До готовности все digest/хеши доступны в клиентском канале; не показывай при обрыве публикации или без отметки прохождения e2e. Повторная публикация того же точно комплекта идемпотентна, подмена запрещена. CI gate потребляет этот контракт на 10.
3. Подключи реальный клиент каталога мастера по конфигурации, закрепление выбранного manifest, поддержку offline/cache с датой и наблюдаемыми ошибками. Используй локальный стенд и test keys.

## Не входит в этап

Установка настоящих секретов подписи или публикация публичного endpoint. Изменение API каталога расширений и несвязанных продуктов.

## Контракты и инварианты

До готовности пакет скрыт; commit, digest и выбранный ранее манифест не подменяются новым тегом. Каталог при сбое не нарушает рабочий DVT и не разрешает небезопасный переход.

## Критерии приёмки

- [ ] `SAC-01`: Stable/RC, совместимость и поддерживаемая платформа фильтруются; каталог скрывает неполный и непроверенный релиз.
- [ ] `SAC-02`: Смена mutable тега и обрыв регистрации не меняют выбранного комплекта и не открывают новый; неверная подпись отклонена.
- [ ] `SAC-03`: При недоступности каталога клиент показывает дату кэша и может продолжить уже проверенный совместимый комплект.

## Проверки

Из venv pytest Distributor для dvt_distribution и offline_download, из venv DVT pytest мастера; контрактные проверки HTTP с тестовыми Registry/object store и тестовыми ключами. Python запускать через venv соответствующего репозитория с абсолютным корнем в `PYTHONPATH` там, где это требует AGENTS.md.

## Ожидаемые артефакты

- `report.md` по шаблону `$feature-coder`: изменения, наблюдаемые результаты, `PASS` / `FAIL` / `NOT_RUN`, команды и соответствие критериям.
- `artifacts/` при необходимости: только очищенные доказательства без секретов и больших пакетов.
- Для изменений DVT, требующих changelog, использовать `dvt-project-ops` и его helper; записать краткую запись по-русски.
