# Контрактные проверки этапа 07

Все ключи и данные были тестовыми. Production CI, хранилище, Registry и DVT не менялись.

| Проверка | Наблюдение |
| --- | --- |
| FastAPI с реальным временным MinIO на loopback | До записи список пуст; отказ e2e и прерванная delivery проверка не создают запись. Два конкурирующих условных Put получают один 200 и один 412. Один подписанный набор выигрывает, другая сборка с тем же normalized RC отвергнута. Повтор точного конверта идемпотентен. GET по версии и digest выдаёт прежние байты; чужой digest даёт 404. |
| Реальный Skopeo и локальный тестовый HTTPS Registry в изолированном контейнере | Leaf manifest и config доступны, а слой отвечает BLOB_UNKNOWN: inspect проходит, copy --preserve-digests запрашивает слой и блокирует публикацию. После возврата слоя точный pin проходит. Запрос для неподходящей архитектуры отвергнут. |
| DVT-клиент с curl и отдельным тестовым CA на Ubuntu | RC без согласия отвергнут; alias наблюдаемой версии и совпадающая ревизия допускают выбор, другая ревизия не допускает. Новый digest над конвертом с подложной Ed25519 подписью отвергнут. После остановки HTTPS-сервера доступны дата и тот же ранее проверенный pin; удалённый manifest не запрашивается повторно. |
| Схема общего формата | JSON Schema Distributor совпала со схемой `SignedRelease.model_json_schema(by_alias=True)` DVT. Тестовый подписанный конверт с исходным форматированием принят обеими сторонами. |

Результаты независимых стендов предоставлены мастер-агентом во время этапа. Локальный pytest дополнительно проверил актуальный отзыв кешированного signer из `.bootstrap/release-trust.json`, отсутствие verifier, отказ от mutable URL при выборе и строгую проверку backend/UI в tagged Git.
