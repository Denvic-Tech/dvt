# Независимая проверка офлайн-комплекта на Ubuntu

Стенд: Ubuntu 24.04 LTS, `linux/amd64`, 2 CPU, около 4 ГиБ RAM и 30 ГБ SSD,
Docker 29.10.0 с containerd image store, Compose 5.7.1. Использовались тестовые
ключи и синтетические данные. Второй Docker с отдельным containerd работал
в Linux network и mount namespaces. Исходный Docker и подключение SSH
оставались вне этого окружения. Внутри изоляции не было внешнего маршрута,
а родной Docker-реестр и Distributor не были доступны. Межконтейнерная сеть
Compose работала локально.

Для подготавливающего CLI применялся защищённый Python venv. В архив вошли пять
независимо сверенных с подписанным APT индексом пакетов Docker Ubuntu. Docker был
уже установлен на VM; установка этих пакетов на пустой ОС в этом прогоне не
выполнялась. Три образа кода этапа собраны по раннему рабочему снимку, остальные
роли — зафиксированные образы приёмки, а UI — явный исторический fixture. Это
доказательство стадий применения, а не приёмка официальной сборки.

Изоляцию поднимали штатной маской прав Docker (после исправления ошибки стенда),
а для раннего снимка включали статическое имя localhost только в namespace.
Ошибка старого machine probe воспроизведена на Linux как `gaierror` одновременно
с доступным HTTPS. Финальная реализация использует числовой loopback TCP,
TLS SNI и проверку сертификата для `localhost`, сохраняет Host и Bearer;
реальный TLS тест с заблокированным resolver прошёл, неверное имя сертификата
отклонено. Восстановленный менеджер на Ubuntu независимо подтвердил тот же
журнал и владение операцией из процесса с заблокированным `socket.getaddrinfo`.

Независимые проверки кода: 117 тестов Distributor; 11 тестов Bash CLI и TLS
с установленным Git Bash вне ограничений песочницы Windows. Результаты
полной матрицы DVT и проверки интерфейса Distributor приведены в отчёте этапа.
