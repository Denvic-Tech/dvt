## Итерация 1 — 16 ноября 2026

### Дефекты

1. **[BLOCKER] Журнал разрешает идти на миграцию обновления мимо окна и копии**
   - Участок: `services/installation_manager/domain/operation_state.py` (`_TRANSITIONS`, `transition_allowed`) и `infrastructure/operation_store.py` (`_checkpoint`).
   - В независимом прогоне через публичные `admit` и `owner.checkpoint` операция `UPDATE` прошла `ADMITTED → PREPARING → PREPARED → MIGRATING`. Результат: `stage migrating backup None`. Стандартные тесты (Windows: 25 прошли, 2 пропущены; Linux: 9 прошли) данный путь не проверяют.
   - По REQ-16–18 и SAC-03 обновление должно пройти через обслуживание и копию. Первичная установка при этом имеет прямой путь из подготовленного комплекта. Переход через `RECOVERING` не должен открывать миграцию обновления без уже зафиксированной точки восстановления.
   - Критерий: отклонять прямой переход `PREPARED → MIGRATING` для `UPDATE`; прямой `PREPARED → RECOVERING` использовать для отдельных операций восстановления, а не как альтернативу фазам штатного обновления. Переход любого `UPDATE` в `MIGRATING` требует ранее записанной ссылки на копию, исходный checkpoint после отказа не меняется. Чистая установка может пройти к миграции без копии; штатное обновление с зарегистрированной копией и продолжение остаются возможными. Физическая проверка копии и проверка БД остаются у этапов 04–06.
