# Построение графа DVT

## До изменений

Найди проект через `list_projects`, разреши неоднозначность имени и используй точный `project_id`. Получи `get_project`, полный `get_project_graph` со всеми страницами, актуальные `graph_revision` и `graph_etag`; изучи узлы, связи, входы и выходы, подграфы, комментарии и расположение. Найди подходящие узлы через `search_nodes` и прочитай их текущие определения через `get_node_definition`. Если MCP не создаёт проекты, создай чистый проект через поддерживаемый интерфейс или запроси его точный ID у пользователя. Прежде чем менять граф, убедись, что он пуст либо предназначен для задачи.

Подробный выбор узлов, соединений и таблиц — в [данные и low-code](data-nodes.md). Предпочитай специализированные low-code узлы для чтения, фильтрации, соединения, агрегации и записи. Не добавляй deprecated узлы. Для SQL/Python и обходных решений оставляй содержательный комментарий с причиной. ID подключения задавай как `connection_ref` у соответствующего `GetExist*Connection`; потребитель получает объект через порт `connection`. Не извлекай credentials.

Перед чтением таблицы проверь каталог: точные имена и типы колонок, nullable, ключи, индексы и колонку сегментации. У `ReadTableFromDBV3` укажи явный непустой список `columns`, включая поля фильтра, join и группировки. Для крупных исторических таблиц оцени объём и выбирай осмысленную временную сегментацию; не считай первичный ID подходящей колонкой автоматически. Сегментация чтения и бизнес-группировка по месяцу — разные операции.

Ставь фильтр до агрегации, когда агрегируются выбранные строки. При вставке узла замени старое ребро двумя новыми и проверь источники обязательных входов. Для `DataFrameGroupByAgg` согласуй длины `source_cols`, `agg_funcs`, `new_cols`.

Перед join со справочником проверь уникальность правого ключа, null и типы по полной комбинации колонок. Нормализуй и дедублицируй детерминированным бизнес-правилом; не скрывай реальную связь многие ко многим. После join проверь кратность ключей и изменение числа строк.

`WriteDataFrameToDBV4` не создаёт таблицу. Проверь целевой объект, при необходимости выполни обоснованный DDL, снова прочитай схему и задай явный `column_mapping`. В полном графе обеспечь зависимость writer от изменения схемы. `truncate` используй только для согласованной полной перезаписи витрины.

Для сравнения таблиц проверь схемы, бизнес-ключ и кратность дублей. Для Excel в S3 передавай `GetExistS3Connection.connection` в `SaveExcel.connection`; путь относителен к bucket/prefix. После `SUCCESS` проверь файл через storage catalog, включая размер и время изменения.

## Применение и завершение

Вызови `validate_graph_changes`, затем примени тот же патч с актуальными revision/etag. При конфликте перечитай граф и пересобери патч. Проверь MCP `isError` и наличие структурированного результата до чтения ID или токенов версии. Сохраняй пользовательскую компоновку и меняй только нужные поля.

Запуск, диагностика, критерий завершения и проверочный список — в [выполнение и проверка](execution.md). MCP patch, генератор патча и UI-экспорт — разные артефакты.
