# Выполнение, диагностика и сдача результата

## Запуск

После применения графа вызови `run_project` с режимом и параметрами, отвечающими задаче; `force_exec=true` используй, когда нужно гарантированно выполнить актуальный граф. Сохрани `task_id` и вызывай `wait_task` до терминального состояния. `QUEUED` и `RUNNING` не означают успех; долгий `RUNNING` при записи или материализации Excel сам по себе не ошибка. Не запускай дублирующую задачу только из-за ожидания.

При `ERROR` прочитай `get_task_logs`, найди конкретный падающий узел и исправь минимально необходимую часть. Затем получи свежие revision/etag, снова validate/apply/run/wait. Для отдельной проверки DDL или ветки можно использовать `target_node_ids`; после неё выполни полный проект, если нужен конечный результат. После timeout сначала проверь статус прежней задачи.

При `503 GATEWAY_UNAVAILABLE` сохрани локальный патч. Не считай неуспешный apply применённым. После восстановления перечитай граф и токены конкурентного изменения, проверь пользовательские правки и только затем продолжай. Ошибка MCP может прийти как `isError=true` с текстом без `structuredContent`.

## Критерий завершения

Для задачи сборки и выполнения графа подтвердить: точный `project_id`; проверенные источники и приёмники; успешную валидацию и применение того же патча; терминальный `SUCCESS` в указанном режиме; отдельную проверку конечной таблицы или файла. Сообщи точное имя результата, путь, существенные допущения и ограничения. Если пользователь просил только подготовить граф без запуска, укажи фактически выполненный объём, не называя его выполненным pipeline.

Различай Python-исходник логики, генератор MCP-патча, JSON-патч и UI-экспорт: последний имеет другой формат. При правке кода синхронизируй относящиеся к задаче локальные артефакты и код DVT. Не переноси значения секретных переменных из UI-экспорта в примеры или отчёт. В отчёте отдельно назови: сохранение графа, результат задачи, обработанные ID, ответы API, дополнительное повторное чтение состояния и непроверенные шаги. `self_test` не подтверждает реальную интеграцию.

[ ] Физическая схема приёмника и column_mapping согласованы
