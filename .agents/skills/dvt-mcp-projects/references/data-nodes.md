# Данные, узлы и хранилища DVT

Существование узла, портов и форматов входа подтверждай через каталог работающей версии.

## Выбор узлов и антипаттерны

| Задача | Типы узлов из исходного руководства |
| --- | --- |
| Подключение | `GetExistDBConnection`, `GetExistS3Connection`, `GetExistFTPConnection`, `GetExistSMBConnection` |
| Чтение и фильтр | `ReadTableFromDBV3`, `DataFrameFilter` |
| Период и агрегаты | `DataFrameConvertToPeriodStart`, `DataFrameGroupByAgg` |
| Объединение | `DataFrameJoin`, `DataFrameUnion` |
| Колонки | `DataFrameRenameColumns`, `DataFrameDropColumns`, `DataFrameCastColumnType` |
| Результат | `WriteDataFrameToDBV4`, `SaveExcel` |

Не создавай deprecated-узлы. Для обычного фильтра, проекции, переименования, join и группировки не используй `ExecuteSQL`, `ReadQueryFromDBV3`, `ExecutePython` или `DataFrameExecCode`, если есть подходящий специализированный узел. Если код или SQL нужен, запиши конкретную причину в комментарии.

## Подключения

ID подключения помещай только во вход `connection_id` соответствующего `GetExist*Connection` как `connection_ref`. Потребителю передавай объект по ребру: `GetExistDBConnection.connection → ReadTableFromDBV3.connection`. Один объект может питать несколько узлов. Строковый ID во входе `connection` reader, writer, SQL или storage-узла — ошибка. Не извлекай credentials.

## Чтение и сегментация

Перед новым или перенастраиваемым `ReadTableFromDBV3` вызови `get_database_table`: проверь сырые имена колонок, типы, nullable, ключи и индексы. Задай явный непустой `columns`; `null` не означает «все». Включи колонки фильтра, join, группировки и сегментации. Явно задай `partition_col`, в том числе при чтении одной партицией.

Оцени данные через `query_database_readonly` или используй свежий профиль того же источника и объёма чтения: число строк, ширину выбранных колонок, null, кардинальность и перекос кандидатов в ключ. Начинай с доступной статистики БД и небольших агрегированных результатов; точные подсчёты и распределения запрашивай при приемлемой стоимости. `max_rows` ограничивает возвращаемый результат, а не работу БД. Preview не доказывает размер таблицы или отсутствие null/перекоса; отмечай приблизительность оценок. Фильтр после reader не уменьшает объём извлечения из источника.

Выбор чтения должен быть осознанным:

- Для подтверждённого небольшого объёма, например около 1 000 обычных узких строк, используй `npartitions=1` без пользовательской группировки и hash buckets. Для регулярного чтения учитывай рост таблицы.
- В остальных случаях обычно оставляй число партиций планировщику: он учитывает строки, ширину выбранных колонок и настройки экземпляра. Осознанный пропуск `partition_grouping` означает автоматический range/hash, а не отказ от анализа. Универсального порога по числу строк нет.
- Предпочитай стабильный скалярный ключ с подходящей кардинальностью и распределением; индекс и отсутствие null полезны. Первичный ID или дата сами по себе не основание выбора.
- Явный `{"mode":"range"}` требует упорядочиваемого ключа без null. `{"mode":"hash"}` подходит для поддерживаемых nullable/неупорядочиваемых ключей; число buckets можно оставить автоматическим. Hash не разделяет одинаковые значения и большую группу null между buckets.
- Для временной группировки сначала оцени диапазон дат и число строк по предполагаемым годам/месяцам/дням, особенно крупнейшую группу. Не выбирай год или месяц только из-за наличия даты либо периода бизнес-отчётности. Например, `{"partition_col":"YM","partition_grouping":{"mode":"granularity","granularity":"year"}}` подходит лишь при подтверждённом распределении.
- Сверяй форматы группировок с документацией текущей ноды. В этой версии нет режимов `single`/`auto` в `partition_grouping`. Пользовательская группировка и явные hash buckets могут определять число сегментов независимо от `npartitions`; не сочетай противоречивые настройки. `max_rows_per_partition` завершает чтение ошибкой при превышении, а не дробит сегмент.

В комментарии reader укажи измерения/оценки, выбранный ключ, стратегию (включая осознанную автоматическую), политику числа партиций и причину. Если профилирование недоступно или истёк тайм-аут, укажи неизвестное; при возможности используй автоматическое число партиций с проверенным совместимым ключом. Не объявляй выбор оптимальным и не фиксируй одну партицию без данных. После запуска проверь доступную диагностику партиций/памяти и пересмотри решение, если фактические результаты расходятся с оценкой.

## Фильтры, группировки, join и union

Если нужны агрегаты только выбранных строк, порядок: `ReadTable → ConvertToPeriodStart → Filter → GroupBy → Output`. Пример условия `contains`:

```json
{"kind":"condition","left":{"type":"column","column":"Article"},"operator":"contains","right":{"type":"literal","value":"Фискальный накопитель"}}
```

`partition_grouping` управляет чтением; `DataFrameConvertToPeriodStart(period="month")` создаёт бизнес-период; `DataFrameGroupByAgg` считает агрегаты. У `source_cols`, `agg_funcs` и `new_cols` должны совпадать длины.

Перед join со справочником проверь уникальность всей комбинации `right_on`, null/пустые ключи, совместимость типов, пробелы, регистр, даты и часовые пояса. Детерминированно нормализуй правую сторону: группировка с бизнес-правилом для атрибутов, активная или последняя запись, либо стабильная сортировка перед `keep=first/last`. Не маскируй реальную связь многие ко многим дедубликацией. После left join при ожидаемой связи многие к одному число строк не должно расти; проверь кратность ключей и строки до/после. Отрази правило в имени и комментарии узла. Если нужен Python, объясни причину дублей, ключ и правило выбора.

Для `DataFrameUnion` заранее сопоставь схемы веток: точные имена, порядок, типы и смысл колонок. Приведи несовместимые поля явно и проверь, нужно ли сохранять дубли или устранять их по бизнес-ключу. Union не заменяет join.

## Запись и DDL

`WriteDataFrameToDBV4` не создаёт базу, схему или таблицу. Проверь точную целевую таблицу. При отсутствии объекта создай его поддерживаемым DDL-инструментом; после DDL перечитай `get_database_table`, сверяй имена, типы и nullable и задай явный `column_mapping`. Для нового поля предпочитай специальный schema-узел; если его нет, используй обоснованный идемпотентный `ExecuteSQL`. Запусти DDL-узел отдельно, подтверди `SUCCESS`, перечитай схему, затем добавь signal-зависимость writer от DDL при полном запуске. `truncate` заменяет всю таблицу: применяй только при явном требовании или подтверждённой полной пересборке витрины.

## Сравнение таблиц, Excel и S3

Для сравнения таблиц получи обе схемы, точные имена и типы, определи бизнес-ключ и проверь уникальность. Если полные строки дублируются, сравнивай кратность. Пустой файл различий имеет смысл только после подтверждения полного чтения и завершения сравнения.

Для Excel: `GetExistS3Connection.connection → SaveExcel.connection`, `DataFrame → SaveExcel.df`. Путь задавай относительно bucket/prefix без повторения этих частей. Явно настрой `sheet_name`, `index`, `header`, `single_file`. `SaveExcel` материализует DataFrame, поэтому запись может быть долгой. После `SUCCESS` проверь путь, размер и `last_modified` через `list_storage`; ошибка preview бинарного XLSX не отменяет наличие файла. `SaveExcel` создаёт файл из DataFrame, а не загружает готовую локальную книгу с оформлением.
