# Запись DataFrame в БД V4

## Назначение и выбор

`WriteDataFrameToDBV4` записывает DataFrame в существующую таблицу БД. Подходит для добавления, полной замены или замены по ключу. Целевые БД, схема и таблица не создаются: подготовьте и проверьте их заранее.

## Входы и настройка

Подайте DataFrame в `df`, а `GetExistDBConnection.connection` — в `connection`. Задайте `table_name`, при необходимости `database_name` и `schema_name`. `write_mode` по умолчанию `append`; `truncate` заменяет все строки; для `upsert` нужен `upsert_config={"key_column":"id"}` с именем целевого ключа. Передавайте `upsert_config` только для upsert. `column_mapping` содержит пары `source_name` / `target_name` и необязательные `dtype` / `nullable`. `on_extra_df_columns` по умолчанию `ignore`, `on_missing_df_columns` — `ignore_if_default`. `chunksize` по умолчанию 1000.

Через MCP изучите цель с помощью `get_database_table` до применения или запуска графа. Подготовьте отсутствующие объекты через `create_database`, `create_schema` или `create_table` по предполагаемым метаданным DataFrame и ограничениям цели, затем перечитайте цель. Рекомендации `agent_description` входных полей описывают подготовку цели и выбор режима записи.

## Результат

Это нода записи: выходного порта DataFrame нет. Системные переменные `target_table` и `rows_written` описывают завершённую запись. `rows_written` — число записанных входных строк, а не итоговый размер таблицы.

## Поведение и ограничения

Служебные колонки DVT удаляются. Сопоставление колонок не меняет схему таблицы. Для отсутствующих колонок действуют default/nullability целевой БД и выбранная политика. Upsert использует одну ключевую колонку: загружает вход во временную таблицу, удаляет совпавшие целевые строки и вставляет подготовленные строки. Это не частичное обновление отдельных полей; входные дубли не устраняются. Truncate/upsert требуют прав на временные таблицы и поддержки диалекта. Для блоков и этапов могут использоваться разные транзакции; атомарность всего запуска не гарантируется. Повтор append может создать дубли; неудачная запись может иметь частичные последствия.

## Примеры

Предположим, `public.order_totals(id, total)` уже существует с совместимыми типами. Подключите объект БД и DataFrame с `id, amount`.

```json
{"table_name":"order_totals","schema_name":"public","write_mode":"append","column_mapping":[{"source_name":"id","target_name":"id"},{"source_name":"amount","target_name":"total"}],"on_extra_df_columns":"error"}
```

Это только значения параметров. Две входные строки добавят две строки. Для замены строк с совпадающим `id` задайте `write_mode="upsert"` и `upsert_config={"key_column":"id"}`, предварительно проверив смысл ключа и уникальность входа.

## Типовые ошибки

Нет целевой таблицы: создайте отдельно и перечитайте её схему. Повторные целевые имена в mapping, несовместимые типы или запрещённые null: исправьте сопоставление/данные по фактической таблице. Нет ключа/config для upsert: задайте целевой ключ. После ошибки проверьте таблицу перед повтором. Truncate используйте только для запланированной полной замены.
