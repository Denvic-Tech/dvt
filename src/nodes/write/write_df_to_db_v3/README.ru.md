# WriteDataFrameToDBV3

Node type: `WriteDataFrameToDBV3`.

## Назначение и выбор

Записывает DataFrame в существующую SQL-таблицу по совпадающим именам колонок. Для явного сопоставления имён источника и назначения выберите WriteDataFrameToDBV4.

## Входы и настройка

Подключите объект SQL-подключения к `connection`, DataFrame — к `df`. Задайте `table_name` и при необходимости `schema_name`/`database_name`. По умолчанию `write_mode=append`; `truncate` очищает таблицу перед вставкой; `upsert` требует `upsert_config` с одним ключом. `chunksize=1000`. Лишние колонки DataFrame по умолчанию обрабатываются как `on_extra_df_columns=ignore`. Для отсутствующих колонок назначения по умолчанию `on_missing_df_columns=ignore_if_default`; `ignore` пропускает их без такой проверки default, `error` отклоняет.

## Результат

Выхода DataFrame нет. Системные переменные `target_table` и `rows_written` сообщают целевую таблицу и счётчик записи.

## Поведение и ограничения

База, схема и таблица должны уже существовать; нода не выводит и не создаёт их структуру. Внутренние колонки DVT удаляются. Null в существующей колонке остаётся значением; отсутствие колонки отличается и может позволить использовать default БД. Ограничения таблицы продолжают действовать. Данные вычисляются и записываются пакетами/партициями; этапы могут фиксироваться отдельно, поэтому ошибка не гарантирует откат всего запуска. Повтор append может дублировать данные; truncate удаляет прежние строки; поддержка upsert и SQL-поведение зависят от диалекта назначения.

## Примеры

Пусть существует таблица orders(id INTEGER, amount INTEGER), а вход содержит строки (1,10), (2,20). Соедините выход объекта подключения с `connection`, DataFrame — с `df`:

```json
{
  "table_name": "orders",
  "write_mode": "append",
  "on_extra_df_columns": "error",
  "on_missing_df_columns": "error",
  "chunksize": 1000
}
```

При соблюдении ограничений добавятся две строки; rows_written сообщит 2. Прежние строки останутся.

## Типовые ошибки

Таблица отсутствует: сначала создайте и проверьте её. Разные имена источника/назначения: переименуйте колонки выше по графу или используйте mapping V4. Для отсутствующей обязательной колонки нужны данные либо допустимый default БД/политика. Ошибки типов, nullable и уникальности требуют согласовать вход с существующей таблицей. Перед повтором проверьте частично выполненную запись.
