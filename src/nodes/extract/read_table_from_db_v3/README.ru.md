# Чтение таблицы БД V3

## Назначение и выбор

`ReadTableFromDBV3` читает таблицу БД в DataFrame с партициями. Используйте для обычного извлечения таблиц, затем применяйте специализированные фильтры, проекции, соединения и агрегаты. `ReadQueryFromDBV3` нужен, когда необходим SQL на стороне источника.

## Входы и настройка

Соедините `GetExistDBConnection.connection` → `connection`; порт принимает объект, а не ID. Задайте `table_name` и при необходимости `database_name` / `schema_name`. Сначала изучите каталог таблицы и передайте явный непустой `columns`; для чтения всех колонок перечислите их все. `partition_col` — точное исходное имя колонки без SQL-кавычек; выбирайте стабильную скалярную колонку без null. `partition_grouping`, `npartitions` и `max_rows_per_partition` настраивают партиционирование чтения. `limit` ограничивает запрошенное чтение. `TTL_CACHE` по умолчанию 0. Параметр `time_zone` объявлен, но текущий путь чтения этой ноды его не применяет.

## Результат

`output` — Dask DataFrame. Выходные метаданные сохраняют доступные комментарии таблицы и колонок источника. Системные переменные: `source_table_name`, `source_schema_name`, `source_db_name`; передавайте их стандартными портами переменных.

## Поведение и ограничения

Группировка партиций управляет физическим чтением, а не бизнес-агрегацией. Партиционирование не гарантирует порядок строк. В режиме метаданных строится пустой DataFrame по схеме источника; это не подтверждает успешность полного чтения. Невычисленные переменные целевой таблицы могут оставить метаданные пустыми. Комментарии источника служат описанием данных. В сохранённом графе нельзя использовать null в `columns` вместо всех колонок: null при обновлении входа через MCP удаляет сохранённое значение.

`npartitions` задаёт целевое число партиций; если его нет, планировщик оценивает число по количеству строк, ширине строки и настройкам экземпляра. Без явной группировки упорядочиваемые ключи без null используют диапазоны, nullable или неупорядочиваемые — hash-сегменты. Явное `{"mode":"range"}` отклоняет null-ключи; `{"mode":"hash","buckets":8}` задаёт hash-сегменты. `max_rows_per_partition` — защитный предел строк одного сегмента: превышение завершает чтение ошибкой, а не разбивает сегмент автоматически. Поэтому неравномерные ключи могут вызвать ошибку даже при большом числе партиций. Ключ также может стать индексом DataFrame; выбранная колонка ключа остаётся в данных. Сегменты читаются отдельно; нельзя предполагать единый согласованный снимок изменяющегося источника между чтениями.

## Примеры

Предположим, в PostgreSQL `public.orders` есть целочисленный `id` без null и числовой `amount`. Подключите объект соединения с БД.

```json
{"table_name":"orders","schema_name":"public","columns":["id","amount"],"partition_col":"id"}
```

Это только значения параметров. Результат содержит выбранные колонки таблицы. Для проверенной колонки даты группировка `{"mode":"granularity","granularity":"year"}` задаёт годовые группы чтения, а не годовые итоги.

## Типовые ошибки

Не найдена таблица/колонка: перечитайте каталог, проверьте БД, схему, регистр и права. Ошибки партиционирования: используйте исходное имя колонки и группировку, совместимую с её типом. Слишком много партиций: изучите распределение данных и настройки вместо произвольного сочетания переопределений.
