# Чтение таблицы БД V3

## Назначение и выбор

`ReadTableFromDBV3` читает таблицу БД в DataFrame с партициями. Используйте для обычного извлечения таблиц, затем применяйте специализированные фильтры, проекции, соединения и агрегаты. `ReadQueryFromDBV3` нужен, когда необходим SQL на стороне источника.

## Входы и настройка

Соедините `GetExistDBConnection.connection` → `connection`; порт принимает объект, а не ID. Задайте `table_name` и при необходимости `database_name` / `schema_name`. Сначала изучите каталог таблицы и передайте явный непустой `columns`; для чтения всех колонок перечислите их все. `partition_col` — точное исходное имя колонки без SQL-кавычек; выбирайте стабильную скалярную колонку без null. `partition_grouping`, `npartitions` и `max_rows_per_partition` настраивают партиционирование чтения. `limit` ограничивает запрошенное чтение. `TTL_CACHE` по умолчанию 0. Параметр `time_zone` объявлен, но текущий путь чтения этой ноды его не применяет.

Определения входов содержат краткие локализованные подсказки UI и отдельные нелокализуемые рекомендации `agent_description`. Прочитайте рекомендации перед настройкой; описанный ниже порядок профилирования применяется и при пропуске настроек партиционирования.

## Результат

`output` — Dask DataFrame. Выходные метаданные сохраняют доступные комментарии таблицы и колонок источника. Системные переменные: `source_table_name`, `source_schema_name`, `source_db_name`; передавайте их стандартными портами переменных.

## Поведение и ограничения

Группировка партиций управляет физическим чтением, а не бизнес-агрегацией. Партиционирование не гарантирует порядок строк. В режиме метаданных строится пустой DataFrame по схеме источника; это не подтверждает успешность полного чтения. Невычисленные переменные целевой таблицы могут оставить метаданные пустыми. Комментарии источника служат описанием данных. В сохранённом графе нельзя использовать null в `columns` вместо всех колонок: null при обновлении входа через MCP удаляет сохранённое значение.

`npartitions` задаёт целевое число партиций; если его нет, планировщик оценивает число по количеству строк, ширине строки и настройкам экземпляра. Без явной группировки упорядочиваемые ключи без null используют диапазоны, nullable или неупорядочиваемые — hash-сегменты. Явное `{"mode":"range"}` отклоняет null-ключи; `{"mode":"hash","buckets":8}` задаёт hash-сегменты. `max_rows_per_partition` — защитный предел строк одного сегмента: превышение завершает чтение ошибкой, а не разбивает сегмент автоматически. Поэтому неравномерные ключи могут вызвать ошибку даже при большом числе партиций. Ключ также может стать индексом DataFrame; выбранная колонка ключа остаётся в данных. Сегменты читаются отдельно; нельзя предполагать единый согласованный снимок изменяющегося источника между чтениями.

## Выбор партиций перед построением графа

Для каждого нового или перенастраиваемого чтения изучите каталог таблицы и оцените данные через `query_database_readonly` (либо используйте свежий профиль того же источника и объёма чтения). Оцените число строк и ширину выбранных колонок. Для кандидатов в ключ проверьте типы, индексы, null, кардинальность и перекос. Предпочитайте доступную статистику источника и небольшие агрегированные результаты; точные подсчёты и запросы распределения выполняйте, когда их стоимость приемлема. `max_rows` ограничивает результат запроса, а не работу БД. Небольшой preview сам по себе не доказывает размер таблицы или отсутствие null и перекоса. Явно отмечайте приблизительные оценки и ограничения выборки. Узел фильтра после reader не уменьшает объём чтения из источника.

Выберите и зафиксируйте политику чтения:

- **Подтверждённое небольшое чтение:** например, около 1 000 обычных узких строк можно читать с `npartitions=1` без пользовательской группировки и hash buckets. Текущему планировщику всё равно нужен ключ партиционирования. Перед фиксацией одной партиции для регулярного чтения учитывайте рост таблицы.
- **Автоматический размер:** обычно не задавайте `npartitions`, чтобы планировщик оценивал число по строкам, ширине выбранных колонок и настройкам экземпляра. Осознанный пропуск `partition_grouping` выбирает автоматический range/hash; он не заменяет исследование данных. Десятки или сотни тысяч строк сами по себе не определяют подходящее число партиций.
- **Явная стратегия:** `{"mode":"range"}` требует упорядочиваемого ключа без null. `{"mode":"hash"}` подходит для поддерживаемых nullable/неупорядочиваемых ключей с автоматическим числом buckets; задавайте `buckets` только с обоснованием. Hash не распределяет одинаковые значения или большую группу null между buckets. Первичный ключ или дата — кандидат, а не достаточное основание выбора.
- **Временная группировка:** перед выбором года, месяца или дня проверьте число строк в предполагаемых периодах, особенно в самом большом. Наличие даты или периода бизнес-отчётности само по себе не обосновывает временные группы чтения. Пользовательские группы определяют сегменты независимо от целевого числа; `npartitions=1` не отменяет несколько временных групп или явное число hash buckets.

В комментарии reader кратко укажите факты (измеренные или оценочные), выбранный ключ, решение о группировке, политику числа партиций и причину. Если профилирование недоступно или завершилось тайм-аутом, укажите неизвестное и при возможности используйте автоматическое число партиций с проверенным совместимым ключом; не заявляйте оптимальность и не фиксируйте одну партицию без оснований. После запуска изучите доступную диагностику партиций и памяти. `max_rows_per_partition` защищает завершением с ошибкой, а не разбивает слишком большую группу.

## Примеры

Предположим, в PostgreSQL `public.orders` есть целочисленный `id` без null и числовой `amount`. Подключите объект соединения с БД.

```json
{"table_name":"orders","schema_name":"public","columns":["id","amount"],"partition_col":"id"}
```

Это только значения параметров. Пример осознанно сохраняет автоматический расчёт числа партиций и выбор range/hash после оценки данных. Если проверка того же источника показала около 1 000 узких строк без ожидаемого значительного роста, добавьте `"npartitions":1` для чтения одной партицией. Результат содержит выбранные колонки таблицы. Для проверенной колонки даты с измеренными размерами периодов группировка `{"mode":"granularity","granularity":"year"}` задаёт годовые группы чтения, а не годовые итоги.

## Типовые ошибки

Не найдена таблица/колонка: перечитайте каталог, проверьте БД, схему, регистр и права. Ошибки партиционирования: используйте исходное имя колонки и группировку, совместимую с её типом. Слишком много партиций: изучите распределение данных и настройки вместо произвольного сочетания переопределений.
