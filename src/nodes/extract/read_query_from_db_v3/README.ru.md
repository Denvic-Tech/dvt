# Чтение результата SQL

Тип ноды: `ReadQueryFromDBV3`.

## Назначение и выбор

Читает результат запроса как DataFrame с партициями. Для обычной выгрузки предпочтительны ReadTableFromDBV3 и low-code преобразования; необходимость SQL источника объясните в комментарии ноды.

## Входы и настройка

Соедините `GetExistDBConnection.connection` → `connection`. Задайте `sql_code`, не `query`, одним SELECT/WITH/set-operation выражением. `partition_col` — точная скалярная колонка/alias результата без SQL-кавычек. `partition_grouping`, `npartitions`, `max_rows_per_partition`, `limit` настраивают чтение. Необязательный `max_concurrent_queries` ограничивает число одновременно выполняемых запросов партиций этой ноды; если параметр не задан, используется значение экземпляра по умолчанию для типа БД.

До настройки партиционирования оцените размер результата запроса, ширину выбранных строк, null, кардинальность и перекос ключа: статистика исходной таблицы может не описывать результат соединений или агрегации. `suggest_read_partitioning` (MCP; Gateway `POST /db-connections/{connection_id}/partitioning-advice`) с этим `sql_code` профилирует колонки результата так же, как ридер встраивает запрос, и возвращает статистику, целевое число партиций и предел строк планировщика, ранжированные готовые настройки и исключённые колонки с причинами; режим запроса поддерживает PostgreSQL, MySQL, Oracle и ClickHouse. Запишите обоснование SQL на стороне источника и решение о партиционировании в комментарий ноды. Дополнительные рекомендации доступны в `agent_description` входных полей.

## Результат

`output` — Dask DataFrame с полями результата запроса.

## Поведение и ограничения

Запрос должен подходить для партиционированного выполнения планировщиком чтения. Предпочтительны стабильные ключи без null. Настройки партиций не агрегируют бизнес-данные и не гарантируют порядок строк. Получение метаданных описывает колонки запроса через источник; невычисленный/пустой SQL может дать пустые метаданные. Это не доказывает успех полного выполнения.

Если `npartitions` не задан, планировщик оценивает целевое число по результату запроса и настройкам экземпляра. По умолчанию сегментация использует диапазоны для упорядочиваемых ключей без null, иначе — hash-сегменты. Границы диапазонов читаются одним сортирующим запросом на ClickHouse, PostgreSQL, SQL Server, MySQL 8 и Oracle; на SQLite, сервере без оконных функций или при ошибке этого запроса — одним запросом на каждую границу. Явный режим range отклоняет null-ключи. `max_rows_per_partition` — предел строк одного сегмента. В пользовательских режимах `partition_grouping` (кроме `range` и `hash`) группа, точное число строк которой превышает предел, разбивается на `ceil(строки / floor(0.8 × max_rows_per_partition))` подсегментов по hash полного значения ключа. Если слишком большую группу нельзя разбить — это группа null, группа из одного значения ключа (например, `as_is`, одно значение `explicit_values` или булево значение) или разбиение потребовало бы больше сегментов, чем допускает лимит партиций экземпляра, — планирование завершается ошибкой до чтения данных с указанием группы, числа её строк и причины. Hash не распределяет одинаковые значения ключа, поэтому одно значение, повторяющееся чаще предела внутри группы префикса, периода или диапазона, по-прежнему вызывает ошибку при чтении, и ошибка называет сегмент. Автоматические и явные range/hash-сегменты не разбиваются. В ClickHouse планировщик перед их построением подсчитывает самое частое значение ключа результата; если это значение или группа null сами по себе больше `max_rows_per_partition`, планирование завершается ошибкой до чтения данных с указанием ключа, значения, числа строк и предела. Другие источники эту проверку пропускают, и такой ключ по-прежнему вызывает ошибку при чтении. Планирование и чтение могут выполнять запрос неоднократно, включая подсчёт и выборку образца; используйте стабильный результат и учитывайте нагрузку на источник. Ключ результата может также стать индексом, оставаясь колонкой данных. При range-сегментации дробный ключ Decimal/numeric становится индексом из точных значений `Decimal`, а его выбранная колонка имеет тип float64.

Каждый сегмент выполняет запрос отдельно. Одновременно выполняется не больше `max_concurrent_queries` запросов сегментов одной ноды. Если параметр не задан, экземпляр применяет значение по умолчанию для типа БД, которое администратор может переопределить или отключить. Остальные сегменты ждут свободного места независимо от числа потоков ноды-потребителя. Больше одновременных запросов — не всегда быстрее: драйверы вроде psycopg и pyodbc замедляются из-за конкуренции потоков, а источники, ограниченные сервером, например ClickHouse, могут ускориться. Ограничение не меняет сегменты, строки и их порядок.

Для ClickHouse запросы сегментов одной ноды используют небольшой пул подключений драйвера вместо нового подключения на каждый сегмент. Если источник сообщает для каждой колонки результата тип целое число до 64 бит, Float32/Float64, Bool, String, Date/Date32, DateTime/DateTime64 или Decimal, в том числе внутри Nullable или LowCardinality, сегменты читаются в формате Arrow, который быстрее преобразует строки и Decimal; значения и типы результата те же, что на обычном пути. Любой другой или неизвестный тип колонки, например UUID, FixedString, Enum, IPv4, Int128, Array, Map, Tuple или JSON, отправляет все сегменты обычным путём. Сегмент, который формат Arrow не может преобразовать так же, например с невалидным текстом UTF-8 или датой вне поддерживаемого диапазона, перечитывается обычным путём, поэтому результат или ошибка не меняются. DateTime64 с точностью, отличной от 0, 3, 6 и 9, читается только через Arrow: если другая колонка отправляет чтение обычным путём, такая колонка вызывает ошибку. Нода работает с ClickHouse через HTTP-интерфейс: подключение с драйвером native на стандартном native-порту (9000, с TLS — 9440) перенаправляется на стандартный HTTP-порт (8123 или 8443) с предупреждением в логе, а native-подключение на любом другом порту завершается ошибкой с просьбой выбрать драйвер http и HTTP-порт сервера.
Ключ результата может также стать индексом, оставаясь колонкой данных.

Для PostgreSQL, если на экземпляре установлен драйвер ADBC PostgreSQL, сегменты читаются в формате Arrow (двоичный `COPY`) через небольшой пул подключений с теми же параметрами подключения, что в несколько раз быстрее на больших чтениях. Это происходит, если каждая колонка результата запроса имеет тип smallint, integer, bigint, numeric, real, double precision, boolean, text, varchar, char, name, date, timestamp, timestamptz, uuid, перечисление (enum), json или jsonb. Чтения меньше 100 000 строк остаются на обычном пути, потому что открытие подключений Arrow стоит дороже, чем экономит. Значения и типы результата те же, что на обычном пути. Любой другой тип колонки, например time, interval, bytea, money, inet или массив, отправляет все сегменты обычным путём, так же как range-индекс по дробному ключу numeric, range-ключ, который не является ни целым числом, ни выбранной колонкой, параметры подключения, которые нельзя воспроизвести точно, и серверы старше PostgreSQL 12 или без клиентской кодировки UTF-8. Сегмент, который формат Arrow не может преобразовать так же, например с датой или временем вне 1–9999 годов или бесконечностью, перечитывается обычным путём, поэтому результат или ошибка не меняются. Если сервер отклоняет подключение Arrow, нода до конца чтения использует обычный путь и пишет предупреждение в лог. Простаивающие подключения Arrow закрываются примерно через секунду после последнего запроса сегмента. Администратор может отключить путь Arrow.

## Примеры

Предположим, подключённая БД содержит эти колонки. Минимальный пример контракта выдаёт `id, amount`; для такого обычного чтения в реальном графе используйте ReadTableFromDBV3, если дополнительная логика источника не оправдывает SQL.

Значения параметров, без оболочки MCP patch:

```json
{
  "sql_code": "SELECT id, amount FROM orders",
  "partition_col": "id"
}
```

## Типовые ошибки

Нет колонки партиции: явно выберите её и задайте alias. Несколько выражений/нетабличный SQL запрещены политикой ноды. Проверьте диалект, права и поддержку группировки для ключа результата. Группа или сегмент больше `max_rows_per_partition`: ошибка планирования называет группу, которую нельзя разбить; ошибка чтения называет сегмент, в котором всё ещё слишком много строк, обычно из-за одного повторяющегося значения ключа. Увеличьте `max_rows_per_partition`, выберите более мелкую группировку или другой ключ. Ошибка планирования со значением ключа партиционирования означает, что это значение или группа null сами по себе больше предела range/hash-сегментов: выберите ключ из рекомендаций `suggest_read_partitioning` или поднимите `max_rows_per_partition` выше указанного числа.
