# HTTP-запрос

Тип ноды: `HTTPRequest`.

## Назначение и выбор

Выполняет один HTTP-запрос и выдаёт JSON-ответ. Подходит для API; автоматической пагинации и уплощения ответа нет.

## Входы и настройка

Задайте `url`, `method` (по умолчанию GET), словари `headers` и `params`. POST/PUT/PATCH могут использовать `json_payload` (объект/список) либо form `data`. Defaults: timeout=30 секунд (1–300), verify_ssl=true, auth={"type":"none"}. Auth: basic/digest username/password, oauth2 token (Bearer), file_cert cert_file_path/key_file_path. Поля auth поддерживают выражения входных/проектных переменных.

## Результат

`output` содержит разобранный JSON-ответ, не статус/заголовки и не сырой текст. Далее используйте JSONEditor/JsonToDataFrame по форме данных.

## Поведение и ограничения

HTTP-ошибки завершают ноду ошибкой; успешный пустой/не-JSON ответ тоже не проходит JSON-разбор. Тело GET очищается. Для методов с телом JSON имеет приоритет над form, кроме legacy-сочетания пустого JSON-объекта и непустого form. OAuth2 использует существующий Bearer token без получения/обновления. Получение метаданных может отправить реальный запрос и повторить его для falsey-ответа; учитывайте побочные эффекты POST/PUT/DELETE. Пути сертификатов относятся к файловой системе worker.

## Примеры

Замените пример URL разрешённым endpoint с JSON. Если он вернёт `{"items":[{"id":1}]}`, объект будет выдан без изменения; пагинация требует отдельной логики графа.

Значения параметров, без оболочки MCP patch:

```json
{
  "url": "https://api.example.com/orders",
  "method": "GET",
  "params": {
    "limit": 100
  },
  "timeout": 30
}
```

## Типовые ошибки

Таймаут/сеть: проверьте доступ к endpoint из worker. 401/403: проверьте выбранную auth-настройку без раскрытия секретов. JSON-ошибка: проверьте содержимое и статус; HEAD/204 обычно не имеют JSON-тела.
