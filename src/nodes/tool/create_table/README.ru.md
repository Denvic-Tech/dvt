# Создание таблицы БД

Тип ноды: `CreateTable`.

## Назначение и выбор

Создаёт таблицу БД из DataFrameMetadata перед запуском записи. Это DDL-операция, не вставка данных.

## Входы и настройка

Подключите объект БД в `connection`. Задайте `table_name`, необязательные database_name/schema_name и непустой `dataframe_metadata.columns`. `table_create_spec` содержит настройки таблицы/ключей диалекта; сверяйтесь с текущей схемой. `on_exists` по умолчанию error, также ignore/recreate.

## Результат

`signal_out` обозначает завершение; системные переменные: target_table_name, target_schema_name, target_db_name. DataFrame-результата нет.

## Поведение и ограничения

Ignore оставляет существующую таблицу без изменения и сверки схемы. Recreate удаляет таблицу и данные до создания новой; последующая ошибка может оставить цель отсутствующей. Нормализация типов/имён/nullability зависит от диалекта, поэтому проверьте итоговую таблицу. Режим метаданных выдаёт сигнал/переменные без DDL. DataFrameMetadata — transport-схема, отличная от TableSchema на выходе ConvertToSchema.

## Примеры

В существующей БД/схеме с DDL-правами и без таблицы order_ids создаётся пустая таблица. Соедините signal_out → writer.signal_in для порядка выполнения, затем проверьте каталог цели перед записью.

Значения параметров, без оболочки MCP patch:

```json
{
  "table_name": "order_ids",
  "on_exists": "error",
  "dataframe_metadata": {
    "columns": [
      {
        "name": "id",
        "dtype": "INT",
        "nullable": false
      }
    ]
  }
}
```

## Типовые ошибки

Уже существует: выберите нужный on_exists, избегая непреднамеренного recreate. Пустые метаданные недопустимы. Отсутствующую схему/БД или DDL-права подготовьте отдельно.
