# ExecuteSQL

Node type: `ExecuteSQL`.

## Назначение и выбор

Выполняет SQL на стороне БД, когда специализированные ноды чтения, преобразования и записи не выражают нужную операцию. При работе через MCP объясните причину выбора в комментарии ноды.

## Входы и настройка

Соедините `GetExistDBConnection.connection` → `connection`; задайте непустой `sql_code` на диалекте источника. Поддерживаемые SQL-шаблоны могут ссылаться на доступные входные/проектные переменные; следуйте текущей схеме SQL-входа.

## Результат

`signal_out` активируется при успехе. SQL, возвращающий строки, заполняет `output` DataFrame с одной партицией. Ровно одна строка результата также создаёт типизированную выходную переменную для каждого уникального непустого имени колонки. SQL без строк не выдаёт табличный результат.

## Поведение и ограничения

Результат запроса материализуется в pandas; для большого сегментированного чтения используйте ReadQueryFromDBV3. SQL без результата может изменять БД и выполняется внутри транзакции с учётом особенностей диалекта. Режим метаданных пропускает выполнение команд без результата и описывает схемы результатов; он не подтверждает успех реального запуска и не выдаёт вычисленные скалярные переменные. Учитывайте побочные эффекты повторного запуска.

## Примеры

При SQL-подключении, поддерживающем этот синтаксис, результат содержит одну строку probe=1, output_variables содержит probe, signal_out активен. Это минимальный пример контракта.

Значения параметров без оболочки MCP-запроса:

```json
{
  "sql_code": "SELECT 1 AS probe"
}
```

## Типовые ошибки

Ошибки синтаксиса SQL и прав доступа передаются вызывающему коду. Переменных может не быть, если результат содержит ноль/несколько строк или повторяющиеся псевдонимы. Не подключайте output как DataFrame для команд без строк результата.
