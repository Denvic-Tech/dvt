# ExecuteProject

Node type: `ExecuteProject`.

## Назначение и выбор

Запускает другой проект DVT. Подходит для координации переиспользуемых дочерних пайплайнов; выдаёт сигнал завершения/отправки, а не данные дочернего проекта.

## Входы и настройка

Задайте `target_project_id` — неизменяемый ID доступного проекта; `target_project_name` служит подписью. По умолчанию `wait_for_completion=false`. При ожидании необязательный `timeout_sec` ограничивает ожидание каждого дочернего запуска; `cancel_on_timeout=false` оставляет его работать после тайм-аута. Необязательный `variables_df` поступает по ребру DataFrame и требует `wait_for_completion=true`. Базовые значения берутся из `input_variables`. По умолчанию `unresolved_variables_policy=error`, `system_variables_policy=include`.

## Результат

`signal_out` становится true после отправки запуска либо после успешного ожидания при включённом режиме. DataFrame и выходные переменные дочернего проекта не возвращаются.

## Поведение и ограничения

Без `variables_df` отправляется один запуск. С ним весь DataFrame вычисляется в памяти; каждая строка запускает один дочерний проект последовательно, колонки строки перекрывают одноимённые базовые переменные. Имена колонок должны быть уникальными непустыми строками; null и скаляры pandas/numpy нормализуются. Пустой DataFrame не создаёт запусков. Режим метаданных задач не запускает. Синхронные вложенные запуски проверяют доступ и доступную ёмкость исполнения; поздняя ошибка не отменяет уже завершившиеся дочерние запуски.

## Примеры

Предположим, выбранный дочерний проект принимает переменную `region`. Подключите DataFrame со строками {region: "north"}, {region: "south"} к `variables_df` и задайте:

```json
{
  "target_project_id": "child-project-id",
  "wait_for_completion": true,
  "timeout_sec": 300,
  "cancel_on_timeout": false
}
```

Запуск north завершится до старта south; сигнал появится после обоих успешных запусков. Без ребра DataFrame эта настройка создаёт один запуск с базовыми переменными.

## Типовые ошибки

variables_df без ожидания не проходит валидацию. Повторяющиеся/пустые имена колонок недопустимы. Для недоступного проекта или недостаточной ёмкости вложенного ожидания исправьте доступ/ёмкость перед повтором. Тайм-аут при cancel_on_timeout=false не означает остановку дочерней задачи; проверьте её перед повторным запуском.
