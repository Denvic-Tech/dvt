# Условное ветвление

Тип ноды: `ConditionalSignalRouter`.

## Назначение и выбор

Выбирает, какая ветка выполнения получает активный сигнал. Маршрутизирует выполнение, а не строки DataFrame; для строк используйте `DataFrameFilter`.

## Входы и настройка

Задайте Boolean `condition` или поддерживаемое выражение. Переменные выражения подайте через `input_variables`. Для зависимости выполнения используйте `signal_in`.

## Результат

`then_signal` активен при true, `else_signal` — при false. Подключите их к downstream `signal_in`. Обычного `signal_out` у этой ноды намеренно нет.

## Поведение и ограничения

Полное выполнение активирует ровно одну ветку. Режим метаданных активирует обе для сбора схем. Кеширование отключено. Доступность ветки в метаданных не означает её выбор при выполнении.

## Примеры

Соедините `then_signal` → action A.signal_in и `else_signal` → action B.signal_in. Полное выполнение активирует входной сигнал A.

Значения параметров, без оболочки MCP patch:

```json
{
  "condition": true
}
```

## Типовые ошибки

Нет signal_out: используйте именованные порты веток. Обе ветки в метаданных: это ожидаемо. Ошибка условия: проверьте Boolean-приведение и входные переменные.
