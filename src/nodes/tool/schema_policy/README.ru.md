# Применение схемы

Тип ноды: `SchemaPolicy`.

## Назначение и выбор

Проверяет или адаптирует колонки DataFrame по явному TableSchema и политикам полей.

## Входы и настройка

Подайте DataFrame → `df` и TableSchema → `schema`. `policy.columns` должен содержать ровно все колонки схемы. Defaults поля: on_missing=error, on_type_mismatch=error; on_missing может быть fill с fill_value или ignore, mismatch — cast, soft_cast или ignore. Общий on_extra_columns по умолчанию error, альтернативы drop/ignore.

## Результат

`output` — DataFrame с настроенными удалениями, добавлениями и преобразованиями.

## Поведение и ограничения

Строгое приведение к целому отвергает дробные значения, мягкое превращает их в null. Мягкие преобразования заменяют неверные данные пропусками. Fill добавляет отсутствующую колонку, а не заполняет null существующей. Реализация применяет политики наличия/типа, а не все ограничения схемы вроде unique или nullable. Работа по партициям ленивая; успех метаданных не доказывает приводимость всех строк.

## Примеры

Подключите схему id:INT, region:STRING и данные `id="7", debug="x"`. Результат — целое id=7 и region=unknown; debug удаляется.

Значения параметров, без оболочки MCP patch:

```json
{
  "policy": {
    "columns": {
      "id": {
        "on_type_mismatch": "cast"
      },
      "region": {
        "on_missing": "fill",
        "fill_value": "unknown"
      }
    },
    "on_extra_columns": "drop"
  }
}
```

## Типовые ошибки

Несовпадение политики/схемы: задайте каждую колонку схемы без лишних ключей. Повторные колонки входа запрещены. Неверное fill/cast: исправьте данные или осмысленно выберите soft_cast и проверьте полученные null.
