# Соединение с БД

Тип ноды: `GetExistDBConnection`.

## Назначение и выбор

Получает сохранённое соединение SQL для следующих нод. Нода использует существующую настройку, не создаёт соединение и не извлекает бизнес-данные.

## Входы и настройка

Задайте `connection_id` доступным сохранённым соединением соответствующего вида. Через MCP используйте `connection_ref` из каталога соединений и актуальную схему значения входа; не передавайте credentials в граф.

## Результат

`connection` — объектный порт DB_CONNECTION. Подключите его к входу `connection` потребителя; один источник может питать несколько нод.

## Поведение и ограничения

При получении проверяются доступ выполняющего пользователя и вид соединения. Кеширование выполнения ноды отключено. Метаданные лениво описывают диалект/возможности каталога; пустой список таблиц не доказывает отсутствие таблиц в БД.

## Примеры

GetExistDBConnection.connection → ReadTableFromDBV3.connection. Настройте эту ноду доступной ссылкой из каталога:

```json
{"connection_id":"<connection_ref>"}
```

Это эскиз значения параметра; замените placeholder и используйте оболочку входа MCP при создании patch. Потребитель получает объект, а не эту строку.

## Типовые ошибки

Не найдено/нет доступа: проверьте соединения, доступные текущему пользователю/токену. Неверный вид: выберите соответствующую ноду соединения. Получение записи каталога не доказывает успешность последующего сетевого обращения или записи.
