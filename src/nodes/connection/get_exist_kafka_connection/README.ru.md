# Kafka Connection

Тип ноды: `GetExistKafkaConnection`.

## Назначение и выбор

Загружает существующее Kafka-подключение, доступное выполняющему пользователю.
Нода остаётся экспериментальной и исключённой из MCP до готовности нод чтения и commit.

## Входы и настройка

`connection_id` — идентификатор каталога (`IO.KAFKA_CONNECTION_ID`), а не имя топика.
Старые числовые идентификаторы преобразуются в строки для поиска.
Реквизиты хранятся в каталоге подключений, а не в переменных графа.

## Выходы

`connection` содержит `KafkaConnectionRecord` для Kafka-потребителей.
Получение записи не создаёт producer и не читает сообщения.

## Поведение и ограничения

Права проверяет существующий сервис подключений. Нода не подтверждает offsets.
Поддерживаются PLAINTEXT, SSL, SASL_PLAINTEXT и SASL_SSL с PLAIN,
SCRAM-SHA-256 или SCRAM-SHA-512. Необязательное `ssl_ca_pem` содержит собственный CA в PEM;
проверки сертификата и имени хоста остаются включены. mTLS этой конфигурацией не поддерживается.
Собственный CA требует сопутствующих изменений исходников db-connections;
опубликованный пакет 1.1.6 их не содержит.

## Примеры

Предусловие: доступное Kafka-подключение с ID каталога `kafka-orders`.

```json
{"connection_id": "kafka-orders"}
```

Соедините выход `connection` со входом `connection` совместимого Kafka-потребителя.
Ожидаемый результат — сохранённая запись без создания producer и изменений offsets.

## Частые ошибки

Недоступный или отсутствующий ID вызывает ошибку поиска. Запись другого типа не проходит проверку.
Для частного TLS-сертификата задайте доверенный CA; не отключайте проверку.
