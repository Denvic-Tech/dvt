# Присоединение Series к DataFrame

Экспериментальная/нестабильная нода `SetColumnToDataFrame`.

Подключите целевой `df` и одну или несколько Series к `column_data`.
Прежний `column_name` с одной Series сохраняет старое поведение присваивания.

Для нескольких назначений:
```json
{"column_bindings": [{"source": "price", "target": "new_price"}, {"source": "quantity", "target": "new_quantity"}], "overwrite_existing": false}
```
Источники — имена подключённых Series, а не ID нод или позиции подключений.
Имена подключённых Series и результатов должны быть уникальными.
Отсутствующие источники и существующие целевые колонки — ошибки; явный
`overwrite_existing` разрешает перезапись существующих целей.
Неиспользуемые источники игнорируются.

Series выравниваются по индексу. Равная длина не гарантирует совпадения строк.
`output` сохраняет целевой DataFrame и присваивает выбранные Series.

В UI используется таблица «источник → результат»; один порт `column_data`
принимает несколько подключений. Политика перезаписи и предпросмотр схемы
находятся под «Дополнительно». Маски к таблице привязок не применяются.

## Переход сохранённых графов

Миграция БД `0063` автоматически переводит существующие ноды на новый контракт.
Имя результата переносится в `column_bindings`; `source: null` означает единственную
подключённую Series, без угадывания её имени во время миграции. Сохраняются
выравнивание по индексу и разрешение перезаписи (`overwrite_existing: true`).
`input_bindings` сохраняет параметры из выражений и подключений: они вычисляются
при каждом запуске через исходные входы. Редактирование соответствующего поля в UI
заменяет только его привязку явным значением. Другие привязки сохраняются.

Старые входы и служебные данные миграции остаются для обратимого отката. Повторный
upgrade не перезаписывает настроенный контракт. Downgrade восстанавливает исходную
запись, если контракт не редактировался; при наличии правок сохраняет новые данные,
а предыдущая версия использует оставленные старые входы.
