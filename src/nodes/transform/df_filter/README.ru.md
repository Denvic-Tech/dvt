# Фильтрация строк

Тип ноды: `DataFrameFilter`.

## Назначение и выбор

Разделяет DataFrame на подходящие и неподходящие строки по структурированным условиям без Python или SQL.

## Входы и настройка

Подключите `df`; задайте `conditions` как `condition` или вложенные группы `and` / `or` с непустыми списками `conditions`. Условие имеет `left`, `operator` и обычно `right`. Операнды — колонка, литерал или каноническое одиночное выражение; при необходимости подключите переменные через `input_variables`. Для `isnull` / `notnull` поле `right` отсутствует.

## Результат

`output` содержит совпавшие строки, `inverted_output` — остальные. Оба сохраняют входную схему.

## Поведение и ограничения

Сравнения: `==`, `!=`, `>`, `<`, `>=`, `<=`; принадлежность: `isin` / `notin`. Текстовые `contains`, `startswith`, `endswith` не учитывают регистр; contains ищет литерал, а не regex. Справа у текстовых/списочных операторов должен быть литерал или выражение. Литералы приводятся к типу колонки. Неопределённые значения маски становятся false. Режим метаданных проверяет структуру/имена и пропускает вход в оба выхода, не вычисляя фильтр.

## Примеры

Во входе `amount` равен `50, 150, null`.

Значения параметров, без оболочки MCP patch:

```json
{
  "conditions": {
    "kind": "condition",
    "left": {
      "type": "column",
      "column": "amount"
    },
    "operator": ">",
    "right": {
      "type": "literal",
      "value": 100
    }
  }
}
```

`output` содержит 150; `inverted_output` — 50 и null. Объединяйте условия через `{"kind":"and","conditions":[...]}` или `or`.

## Типовые ошибки

Неизвестные колонки, пустые группы и неверные операнды вызывают ошибку. Для явной проверки null используйте isnull/notnull; сравнения порядка с null-литералом запрещены. Актуальный контракт условий см. в `additional_schema.filter_rules_spec`.
