# Каталог релизов мастера

Публичный [install.sh](customer_installation.md) получает каталог по HTTPS.
Для частного каталога используются `--catalog-origin` и `--catalog-ca`.
При ручном запуске `host_bootstrap.py` конфигурация каталога задаётся через
`--release-catalog-config <file.json>`, а дополнительный CA — через
`--release-catalog-ca <file.pem>`. Файл содержит доверенный HTTPS origin
Distributor и публичную политику Ed25519. Подготовка описана в
[руководстве по ручному bootstrap и частной проверке](bootstrap_candidate.md).

```json
{
  "origin": "https://dvt.distribution.denvic.tech",
  "trust": {
    "roots": {"approved-root-id": "<64 hex chars from the approved bootstrap trust root>"},
    "revoked_signers": []
  }
}
```

Bootstrap сохраняет origin и исходную политику в закрытом `.bootstrap/host.json`.
Данные дистрибутива сохраняются при наличии и не влияют на подбор релизов.
Дополнительный владелецкий файл
`.bootstrap/release-trust.json` (0600) меняет политику для новых выборов и
применения уже подготовленной операции. Сломанный override не отключает его
в пользу старого ключа. По умолчанию curl использует системные CA. Передайте
`--release-catalog-ca <file.pem>`, чтобы загрузчик сохранил дополнительный
CA bundle в `.bootstrap/release-catalog-ca.pem` (0600) до старта мастера.
В этих файлах хранятся публичные сертификаты и корни доверия.

- `GET /api/releases?channel=stable` под существующей защитой мастера возвращает
  `catalog_fetched_at`, `catalog_error`, `source_error`, подтверждённый
  `source` (или пустое значение), `trust_configured`, список достижимых
  `releases`, рекомендуемый stable и `paths` (массивы последовательных версий).
  Для установленного экземпляра версия связана с наблюдаемым digest Gateway,
  а исходная ревизия и идентификатор проверяются в PostgreSQL. Legacy и
  незавершённая установка без подтверждённого источника не считаются пустым хостом.
  При отсутствии пути `recommended_stable` равен `null`. RC находится в отдельном
  списке через `channel=rc`. Мастер установки запрашивает `channel=all` для
  общего списка стабильных и предварительных версий. Ответ также содержит
  `first_steps` с ближайшим переходом для каждой достижимой цели.
- `POST /api/releases/selection` принимает `version`, `manifest_digest` и,
  только для выбранного RC, `confirm_rc: true`. Он возвращает `pin` и `manifest_url`,
  где `pin` содержит `release_id` и digest конверта. Это выбор ближайшего
  подписанного перехода с повторной проверкой версии, схемы, платформы и подписи;
  если путь длиннее, сперва выберите первый промежуточный релиз. Сам вызов не
  создаёт операцию и не меняет рабочий DVT. Операторский
  `POST /api/operator/operations` принимает установку или обновление с
  `Idempotency-Key`. Для обновления он проверяет и закрепляет маршрут до выбранной
  цели, включая промежуточные релизы. Основной UI и независимый мастер показывают
  маршрут по общему ID. Executor повторно проверяет источник, пакет и план.
  [Браузерный сценарий](operator_browser.md)
- При недоступном Distributor мастер возвращает сохранённый список с датой
  последней успешной загрузки и причиной ошибки. Метаданные из списка лишь
  подсказывают путь. Уже выбранные байты манифеста находятся в защищённом
  `.bootstrap/release-catalog/` по digest и повторно проверяются с актуальным
  доверием; неподтверждённая ранее запись не становится доверенной без сети.
  Подготовленная операция продолжает пользоваться своим staging и pin, а
  рабочее приложение и API журнала от каталога не зависят. Истечение/отзыв
  подчиняются [политике staging](verified_staging.md) и [применения](migration_apply.md).
