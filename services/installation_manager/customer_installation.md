# Установка и обслуживание DVT через подписанный каталог

Первый профиль приёмки использует Debian 13 и Ubuntu 24.04 LTS с systemd,
локальными Docker Engine и Compose на Linux amd64, PostgreSQL и Valkey из
поставки, одним воркером и опциональным AI MCP. Установщик получает готовую
версию из каталога независимо от дистрибутива и его версии. Для установки
нужны работающий Docker с Linux-образами из манифеста и Compose, а для
регистрации службы восстановления — systemd. Версии Docker и Compose, CPU,
RAM, место и inode проверяются по манифесту выбранной версии.

## Первый запуск

Войдите на хост в административный терминал, например через `ssh -t`,
и выполните команду:

~~~bash
bash <(sudo curl -fsSL https://raw.distribution.denvic.tech/dvt/install.sh)
~~~

Команда без аргументов запускает мастер из последнего готового stable для этого хоста. Версию DVT пользователь выбирает в мастере.
Чтобы установить последний готовый RC, укажите канал явно:

~~~bash
bash <(sudo curl -fsSL https://raw.distribution.denvic.tech/dvt/install.sh) --channel rc
~~~

Чтобы установить конкретную версию, укажите её номер:

~~~bash
bash <(sudo curl -fsSL https://raw.distribution.denvic.tech/dvt/install.sh) --version 1.24.0-rc8
~~~

Если запрошенная версия отсутствует или несовместима с хостом, установка
останавливается. При явном выборе версии или канала мастер предложит закреплённую установщиком версию.
При повторном запуске для существующего экземпляра достаточно прежней команды
без аргументов.

На чистом хосте версия с новым мастером определяет адрес сервера и выводит
ссылки для входа с сервера и с рабочего компьютера. Порт мастера по умолчанию —
8888. Если он занят и порт не задан явно, установщик выбирает свободный.
Оставьте установочный скрипт работающим до отправки формы.

При первом запуске мастера без `--public-url` установщик дополнительно запрашивает
внешний IP по HTTPS у ipify (до двух секунд). Если получен публичный адрес
подходящего семейства, в консоли появится ещё одна ссылка с портом мастера.
В форме установки первым будет внешний адрес DVT, следом — локальный, если он
отличается. Оба адреса можно изменить. При недоступности ipify или некорректном
ответе мастер использует прежние локальные адреса. Повторный запуск существующего
экземпляра использует сохранённые настройки.

Если сервер выходит в интернет через прокси или адрес входящего NAT отличается от
исходящего, укажите адрес DVT явно, например `--public-url https://dvt.example.org`.
В этом случае установщик пропускает запрос к ipify. При пробросе порта мастера на
другой внешний порт подставьте его в консольную ссылку перед открытием.

Для однострочной команды нужны Bash, POSIX shell, curl, systemd и права root
или sudo. На чистом хосте установщик может установить Docker и Compose.
Для заранее настроенного запуска используйте `--non-interactive --install-docker`,
`--public-url` и `--dir`. При нестандартном containerd image store укажите
`--containerd-root`.

На чистом хосте launcher получает дескриптор выбранного готового релиза
для текущей ОС по HTTPS, проверяет размер и SHA-256 bootstrap и передаёт
закреплённый по digest образ мастера. Ошибка HTTPS, отсутствие готового
релиза или несовпадение хеша останавливают запуск до изменения хоста.
Повтор той же команды для экземпляра с сохранённым bootstrap проверяет
его локальный SHA-256 и использует сохранённые настройки и журнал.
При временной недоступности каталога повтор может продолжить уже
закреплённую операцию. Новые операции требуют доступного каталога.

## Вход в мастер и первый администратор

В релизе с прямым HTTP-доступом откройте полную ссылку `Manager` из терминала.
Она содержит адрес вида `http://<хост>:8888/` и одноразовый код после `#pairing=`.
Если сервер за NAT и мастер вывел внутренний IP, в версии с поддержкой внешних
адресов замените в ссылке хост и при необходимости порт на внешний адрес мастера.
Сохраните фрагмент `#pairing=…` целиком.
Ссылка действует десять минут. Для новой ссылки повторите команду в интерактивном
терминале. При автоматическом запуске скрипт печатает только адрес. Порт должен
быть доступен с рабочего места оператора. Используйте доверенную сеть или
ограничьте доступ к порту на стороне ВМ: HTTP передаёт данные открытым текстом.

Для уже выпущенного `1.24.0-rc8` и существующих установок с локальным HTTPS
действуют команды доступа, выведенные их мастером.

В списке **Версия DVT** выберите стабильный или предварительный релиз.
В форме укажите адреса DVT, путь установки (по умолчанию `/var/lib/dvt`),
порт приложения, число воркеров и состояние AI MCP. Нажмите **Установить DVT**.
Мастер показывает журнал и стадии выполнения. После успешной установки нажмите
**Открыть DVT**. В новой вкладке пройдите первичную настройку и создайте первого
администратора.
[Сценарий браузера](operator_browser.md)

## Обновление из основного интерфейса

Суперадминистратор открывает **Профиль → Обновление DVT**, проверяет
фактическую версию и ревизию и выбирает разрешённый переход.
Подготовка загружает образы и проверяет ресурсы при доступном приложении.
Сохраните ID операции и адрес независимого мастера. Перед применением
проверьте план и готовность окна обслуживания. Подтвердите применение,
дождитесь завершения непрерываемых задач и следите за журналом по тому же ID.
При отказе используйте доступное действие в журнале.

## Предыдущий мастер и аварийная установка

В DVT `1.22.0` и `1.23.0` откройте обновление в профиле и укажите точную стабильную
версию или `latest`. Для `latest` сервис распространения фиксирует последний готовый
стабильный релиз при запросе Compose. Во время обновления интерфейс DVT может быть
временно недоступен. После подключения он покажет результат по исходному ID.

Менеджер принимает существующую установку на `1.24.0`, сохраняет данные и настройки
и применяет последующие переходы до выбранной версии. Отдельно устанавливать
промежуточные версии на сервере не требуется.

Для явного запуска прежнего установщика предусмотрена команда:

~~~bash
bash <(sudo curl -fsSL https://raw.distribution.denvic.tech/dvt/services/installation_manager/install.sh)
~~~

Для аварийного ручного запуска защищённого мастера используйте заранее
проверенный bootstrap, утверждённый образ и выданные администратором
TLS-материалы. [Ручное закрепление и частная приёмка](bootstrap_candidate.md)

## Офлайн, резервная копия и отказ

На подключённой машине получите подписанный архив для точного релиза,
дистрибутива, режима и профиля. Для офлайн-хоста заранее подготовьте доверенные
CLI, CA и зависимости с подходящим Python ABI. Установка и обновление
используют общий журнал и проверку образов. [Офлайн-команды](../../scripts/offline/README.md)

Согласуйте с владельцем экземпляра срок хранения предыдущего подтверждённого
комплекта и минимум одной проверенной точки восстановления на отдельном диске
или носителе. Запишите место хранения, круг доступа и срок очистки.
Длительность восстановления и допустимая потеря данных зависят от объёма
согласованной копии и результатов теста на отдельной чистой ВМ.

При ошибке скачайте диагностику из мастера по ID. Для экземпляра,
созданного публичной командой, административные действия используют
сохранённый launcher и закреплённый образ:

~~~bash
sudo /bin/sh /var/lib/dvt/.bootstrap/host-launch.sh resume /var/lib/dvt
sudo /bin/sh /var/lib/dvt/.bootstrap/host-launch.sh recover-manager /var/lib/dvt \
  --operation-id "$OPERATION_ID"
~~~

Тот же launcher принимает `restore-start` и `maintenance` с ID операции.
Используйте фактический каталог экземпляра. Для ранее созданных
экземпляров и офлайн-поставок применяются их сохранённые команды. Для восстановления БД сначала подтвердите digest
копии и момент отсечения записей, затем восстановите предыдущий комплект,
проверьте вход и контрольный проект и возобновите работу через защищённый
мастер. [Команды восстановления и переход со старой установки](recovery.md)
