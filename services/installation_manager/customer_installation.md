# Установка и обслуживание DVT через подписанный каталог

Первый профиль приёмки использует Debian 13 и Ubuntu 24.04 LTS c systemd,
локальными Docker Engine и Compose на Linux amd64, PostgreSQL и Valkey из
поставки, одним воркером и опциональным AI MCP. Начинайте установку после
появления готовой версии для вашей ОС и профиля в каталоге. Версии Docker и
Compose, предел воркеров, CPU, RAM, место и inode проверяются по манифесту
этой версии. Для Debian 12, других архитектур, внешнего PostgreSQL и
корпоративных сетевых профилей требуется отдельный проверенный маршрут.

## Первый запуск

Получите из доверенного административного канала `bootstrap.py` с его SHA-256,
digest образа мастера, конфигурацию каталога и публичный корень подписи.
Сверьте SHA-256 файла по подписанной поставке перед запуском.
Подготовьте PEM-сертификат с SAN `DNS:localhost`, приватный ключ мастера и CA,
которой доверяет браузер оператора. Внешний HTTPS-адрес DVT и его
обратный прокси настраиваются отдельно от loopback-адреса мастера.

Содержимое `catalog.json` задаёт оговоренные HTTPS origin и корни подписи.
Пример доверия и именование разрешённых Registry описаны в
[контракте каталога](release_catalog.md).

~~~bash
sudo /usr/bin/python3 ./bootstrap.py bootstrap --non-interactive \
  --dir /var/lib/dvt --project dvt --port 8888 \
  --public-url https://dvt.example.org \
  --manager "$APPROVED_MANAGER_DIGEST_REF" \
  --release-catalog-config "$CATALOG_CONFIG" \
  --cert "$MANAGER_TLS/cert.pem" --key "$MANAGER_TLS/key.pem" \
  --ca "$MANAGER_TLS/ca.pem" --containerd-root /var/lib/containerd
~~~

Замените значения на выданные администратором. Укажите фактический каталог
containerd image store. При Docker с другим хранилищем опустите
`--containerd-root`. Для частного CA каталога и артефактов передайте
`--release-catalog-ca "$DIST_CA"`; Docker Registry использует отдельное
доверие Docker Engine. На чистой ОС используйте `--install-docker` после
согласования установки системных пакетов или снимите `--non-interactive`
и подтвердите установку в терминале. При повторе той же команды bootstrap
находит существующий экземпляр и возвращает его адрес.

## Защищённый доступ и первый администратор

Откройте HTTPS-адрес мастера, показанный bootstrap. Для доступа с рабочего
места установите SSH tunnel с проверкой SSH host key.

~~~bash
ssh -N -L 127.0.0.1:8888:127.0.0.1:8888 administrator@dvt-host
~~~

Откройте `https://localhost:8888` в браузере и введите одноразовый код
из защищённого терминала. Он действует десять минут. Если срок истёк,
запустите `sudo /usr/bin/python3 ./bootstrap.py bootstrap --non-interactive
--dir /var/lib/dvt --new-pairing-token` в административном терминале. Укажите тот же порт в
SSH tunnel, если на хосте выбран другой порт мастера. TLS-проверка в браузере
должна проходить для `localhost`.

В мастере выберите рекомендуемый стабильный релиз или подтвердите RC.
В дополнительных настройках выберите порт приложения, воркеры и AI MCP.
Нажмите **Установить DVT**. После подтверждения рабочего стека перейдите
по одноразовому предложению первичной настройки и создайте первого
администратора. После первого входа оставайтесь в основном UI.
[Сценарий браузера](operator_browser.md)

## Обновление из основного интерфейса

Суперадминистратор открывает **Профиль → Обновление DVT**, проверяет
фактическую версию и ревизию и выбирает разрешённый переход.
Подготовка загружает образы и проверяет ресурсы при доступном приложении.
Сохраните ID операции и адрес независимого мастера. Перед применением
проверьте план и готовность окна обслуживания. Подтвердите применение,
дождитесь завершения непрерываемых задач и следите за журналом по тому же ID.
При отказе используйте доступное действие в журнале.

## Офлайн, резервная копия и отказ

На подключённой машине получите подписанный архив для точного релиза,
дистрибутива, режима и профиля. Для офлайн-хоста заранее подготовьте доверенные
CLI, CA и зависимости с подходящим Python ABI. Установка и обновление
используют общий журнал и проверку образов. [Офлайн-команды](../../scripts/offline/README.md)

Согласуйте с владельцем экземпляра срок хранения предыдущего подтверждённого
комплекта и минимум одной проверенной точки восстановления на отдельном диске
или носителе. Запишите место хранения, круг доступа и срок очистки.
Длительность восстановления и допустимая потеря данных зависят от объёма
согласованной копии и результатов теста на отдельной чистой ВМ.

При ошибке скачайте диагностику из мастера по ID. Команда
`sudo /usr/bin/python3 /var/lib/dvt/.bootstrap/host_bootstrap.py resume
--dir /var/lib/dvt` продолжает активную операцию с тем же ID. При потере
мастера после старта обновления используйте подкоманду
`recover-manager --dir /var/lib/dvt --operation-id "$OPERATION_ID"`
того же скрипта из административного терминала. Для восстановления БД сначала подтвердите digest
копии и момент отсечения записей, затем восстановите предыдущий комплект,
проверьте вход и контрольный проект и возобновите работу через защищённый
мастер. [Команды восстановления и переход со старой установки](recovery.md)
